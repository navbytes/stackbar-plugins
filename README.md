# Stackbar Plugins

The curated plugin store for [Stackbar](https://github.com/navbytes/stackbar),
the native macOS menu-bar host for live plugins written in Swift.

Every plugin here is one Swift file. It is reviewed, builds against a released
StackbarKit, renders every surface it declares in CI, and is signed by
navbytes before it is published. Stackbar builds each plugin on your Mac,
runs it in its own sandboxed process, and asks before it may use anything its
manifest declares.

## Install

Stackbar lists this store first: **Settings → Store**. Everything here is
public, so there is no account and no token. From a terminal:

```sh
stackbarctl index search https://navbytes.github.io/stackbar-plugins/index.json
stackbarctl install --index https://navbytes.github.io/stackbar-plugins/index.json io.navbytes.stackbar.plugins.world-clock
```

Stackbar checks for updates daily and installs them unless you turn that off.
An update that asks for something new waits for your approval.

## How it works

- `Package.swift` makes each `<Category>/<Name>/<Name>.swift` an executable
  target against StackbarKit at the pinned Stackbar tag, so `swift build`
  checks every plugin.
- Pull requests run `scripts/check.sh` on Linux and macOS: build, house rules,
  a render of every surface, and on macOS a short soak in the App Sandbox. The
  job summary lists what each plugin asks for.
- A push to `main` runs `scripts/publish.sh`: new versions are signed with the
  navbytes key and added to the `gh-pages` branch next to the old ones, and the
  signed `index.json` is rebuilt. Published versions are never rewritten.
- `revoked.json` withdraws a published version; Stackbar removes it from Macs
  that installed it.
- A nightly canary builds everything against Stackbar's `main`.
